---
title: Effect Helpers
description: Promise bridging and timeout helpers for effects
---

## What

`withPromise()` bridges a promise to actor events. `withTimeout()` arms a timeout that fires an event.

## Why

A promise that resolves after the machine left the state, or a timer that fires after exit, would send a stale event. Both helpers check `signal.aborted` before emitting, so late results do nothing, and both use the actor's clock, so tests stay deterministic on `VirtualClock`.

## How

### withPromise

```ts
withPromise({
  promise,
  signal,
  emit,
  events: {
    success: (data) => ({ type: "paymentOk", payload: data }),
    error: (err) => ({ type: "paymentFail", payload: err }),
  },
});
```

- Awaits the promise
- On resolve: calls `success`, emits resulting event
- On reject: calls `error`, emits resulting event
- Checks `signal.aborted` before each emit
- Mapper return value must be `{ type, payload? }` envelope

Sugar equivalent:

```ts
setup: (m) => {
  m.effect(submitting, {
    name: "chargeCard",
    fn: (input) => {
      const s = input.context.get();
      withPromise({
        promise: chargeCard(s.paymentInfo!.cardNumber),
        signal: input.signal,
        emit: input.emit,
        events: {
          success: (orderId) => paymentOk.create({ orderId }),
          error: (reason) => paymentFail.create({ reason: String(reason) }),
        },
      });
    },
  });
};
```

### Errors as values

When the port returns `Promise<Either<PaymentError, string>>`, map the result with `Either.match` (from `@mantaq/utils`) inside `success`. No extra helper is needed and neither branch needs a cast:

```ts
type PaymentEvent =
  | { type: "paymentOk"; payload: { orderId: string } }
  | { type: "paymentFail"; payload: { reason: string } };

m.effect(submitting, {
  name: "chargeCard",
  fn: (input) => {
    const s = input.context.get();
    withPromise({
      promise: chargeCard(s.paymentInfo!.cardNumber),
      signal: input.signal,
      emit: input.emit,
      events: {
        success: (result) =>
          Either.match(result, {
            onLeft: (reason): PaymentEvent => paymentFail.create({ reason: reason.message }),
            onRight: (orderId): PaymentEvent => paymentOk.create({ orderId }),
          }),
        error: (reason) => paymentFail.create({ reason: String(reason) }),
      },
    });
  },
});
```

Annotating both handlers with the event union lets `Either.match` infer one result type.

### withTimeout

```ts
withTimeout(800, { input, event: () => paymentTimeout.create() });
```

- Schedules timeout on the actor's clock
- On fire: checks `signal.aborted`, calls `event`, emits resulting event
- State exit aborts the effect signal, no emit after exit
- Warns on invalid `ms`

Equivalent without sugar:

```ts
m.effect(submitting, {
  name: "startSubmitTimeout",
  fn: ({ clock, signal, emit }) => {
    clock.setTimeout(800, { signal, cb: () => emit(paymentTimeout.create()) });
  },
});
```

### VirtualClock testing

```ts
import { VirtualClock } from "@mantaq/core";
import { matches } from "@mantaq/sugar";
import { createCheckoutActor, submitBasicInfo, submitPayment, submitShipping } from "./checkout";

const clock = VirtualClock();
const { actor: checkout } = createCheckoutActor({
  clock,
  chargeCard: () => new Promise<string>(() => {}), // never answers
});
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
checkout.send(submitPayment.create({ cardNumber: "4242 4242 4242 4242" }));
clock.advance(800); // triggers timeout synchronously
matches(checkout, "error"); // true: no answer in 800ms
```

Same clock, same inputs, same trace.
