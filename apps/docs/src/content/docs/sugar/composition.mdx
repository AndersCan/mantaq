## What

`actorSpec`, `definePart` and `withParts` slice one actor's `setup` into parts, each in its own file. Parts are not child actors: they share the actor's context and event loop.

## Why

A `setup` body that grows past one screen is hard to read and review. Splitting it by concern (state-local handlers, cross-state handlers, effects) keeps each file short, and the actor composes them with one call. With a few states and transitions, keep `setup` inline.

## How

### 1. Declare the actor spec

```ts
// checkout-spec.ts
import { state, event } from "@mantaq/core";
import { actorSpec } from "@mantaq/sugar";
import type { CheckoutContext } from "./checkout";

export const basicInfo = state("basicInfo")();
export const payment = state("payment")();
export const submitting = state("submitting")();
export const success = state("success")().final();
export const error = state("error")();

export const submitBasicInfo = event("submitBasicInfo")<{ email: string; name: string }>();
export const submitPayment = event("submitPayment")<{ cardNumber: string }>();
export const paymentOk = event("paymentOk")<{ orderId: string }>();
export const paymentFail = event("paymentFail")<{ reason: string }>();
export const paymentTimeout = event("paymentTimeout")();

const initialContext: CheckoutContext = {};

export const checkout = actorSpec({
  inputs: [submitBasicInfo, submitPayment],
  internal: [paymentOk, paymentFail, paymentTimeout],
  states: [basicInfo, payment, submitting, success, error],
  initial: basicInfo,
  context: initialContext,
});
```

Options move out of `Actor({ ... })` into an `actorSpec` value. This becomes the
type anchor every part references.

`actorSpec` narrows state and event arrays to their literals, no `as const`
needed. Context stays mutable, part handlers read and write with no casts.

### 2. Define parts

`definePart` wraps a setup slice. The builder is the actor's own. Import
the spec `type`-only as anchor, refs as values.

```ts
// parts/basic-info.ts
import { definePart } from "@mantaq/sugar";
import type { checkout } from "../checkout-spec";
import { basicInfo, payment, submitBasicInfo } from "../checkout-spec";

export const basicInfoPart = definePart<typeof checkout>((m) => {
  m.on(basicInfo, {
    event: submitBasicInfo,
    to: [payment],
    handler: (event, opts) => {
      const cur = opts.context.get();
      cur.basicInfo = event.payload;
      opts.context.set(cur);
      return { state: payment };
    },
  });
});
```

Effects stay with their state:

```ts
// parts/submitting.ts
import { definePart, withPromise, withTimeout } from "@mantaq/sugar";
import { chargeCard } from "../checkout";
import type { checkout } from "../checkout-spec";
import {
  error,
  paymentFail,
  paymentOk,
  paymentTimeout,
  submitting,
  success,
} from "../checkout-spec";

export const submittingPart = definePart<typeof checkout>((m) => {
  m.effect(submitting, {
    name: "chargeCard",
    fn: (input) => {
      const s = input.context.get();
      withPromise({
        promise: chargeCard(s.paymentInfo!.cardNumber),
        signal: input.signal,
        emit: input.emit,
        events: {
          success: (orderId) => paymentOk.create({ orderId }),
          error: (reason) => paymentFail.create({ reason: String(reason) }),
        },
      });
      withTimeout(800, { input, event: () => paymentTimeout.create() });
    },
  });
  m.on(submitting, { event: paymentOk, to: [success], handler: () => ({ state: success }) });
  m.on(submitting, { event: paymentFail, to: [error], handler: () => ({ state: error }) });
  m.on(submitting, { event: paymentTimeout, to: [error], handler: () => ({ state: error }) });
});
```

Cross-state handlers go in their own part too. Reach the actor through
`opts.actor`, no closure needed.

### 3. Compose

```ts
// checkout-actor.ts
import { withParts } from "@mantaq/sugar";
import { checkout } from "./checkout-spec";
import { basicInfoPart } from "./parts/basic-info";
import { submittingPart } from "./parts/submitting";

export const checkoutActor = withParts(checkout, basicInfoPart, submittingPart);
```

Pass `clock`, `regions`, or `internalBudget` through the spec the same way
as `Actor({ ... })`.

### 4. Mix with inline code

`use` registers a part inside a hand-written setup:

```ts
// checkout-inline.ts
import { Actor, VirtualClock } from "@mantaq/core";
import { use } from "@mantaq/sugar";
import { basicInfo, checkout } from "./checkout-spec";
import { basicInfoPart } from "./parts/basic-info";
import { submittingPart } from "./parts/submitting";

const actor = Actor({
  ...checkout,
  clock: VirtualClock(),
  setup: (m) => {
    use(m, basicInfoPart);
    use(m, submittingPart);
    m.effect(basicInfo, {
      name: "trackBasicInfoVisit",
      fn: (input) => {
        // an extra inline effect; parts and inline code share the same builder
      },
    });
  },
});
```

### Rules

- All parts share one `typeof <spec>` anchor. Wrong anchor = compile error.
- Last handler wins for (state, event) pairs, regardless of registration source.
- Effects append. Multiple effects run on state entry.
- `onAny` handlers run alongside specific state handlers, not replacing them.
- No runtime indirection. Parts write to the same transition/effect maps.
