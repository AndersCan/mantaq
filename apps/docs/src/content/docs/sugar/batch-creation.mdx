---
title: Batch Creation
description: Create multiple states and events in one call
---

## What

`states()` and `events()` create many refs in one call, returning a typed record keyed by name.

## Why

A checkout with six states and seven events needs thirteen `state(...)()` and `event(...)()` calls that repeat every name. Two calls replace them. With only a few refs, the plain `state("basicInfo")()` form stays clearer.

## How

### states

```ts
import { states } from "@mantaq/sugar";

const { basicInfo, shippingAddress, payment, submitting, success, error } = states(
  "basicInfo",
  "shippingAddress",
  "payment",
  "submitting",
  { name: "success", final: true },
  "error",
);
```

Finality declared at creation via `{ name: "<id>", final: true }`. No `.final()` call.

### events

```ts
import { events } from "@mantaq/sugar";

const {
  submitBasicInfo,
  submitShipping,
  submitPayment,
  back,
  paymentOk,
  paymentFail,
  paymentTimeout,
} = events(
  "submitBasicInfo",
  "submitShipping",
  "submitPayment",
  "back",
  "paymentOk",
  "paymentFail",
  "paymentTimeout",
);
```

### Return type

`states()` returns `{ [K in T]: StateRef<K> }`. Dot or bracket access:

```ts
const s = states("basicInfo", "payment");
s.basicInfo; // StateRef<"basicInfo">
s["payment"]; // StateRef<"payment">
```

Destructure or keep the record:

```ts
const { basicInfo, payment } = states("basicInfo", "payment");
```

### With an actor

```ts
const { basicInfo, payment, success } = states("basicInfo", "payment", {
  name: "success",
  final: true,
});
const { submitBasicInfo, submitPayment } = events("submitBasicInfo", "submitPayment");

const checkout = Actor({
  inputs: [submitBasicInfo, submitPayment],
  states: [basicInfo, payment, success],
  initial: basicInfo,
  setup: (m) => {
    m.on(basicInfo, { event: submitBasicInfo, to: [payment], handler: () => ({ state: payment }) });
    m.on(payment, { event: submitPayment, to: [success], handler: () => ({ state: success }) });
  },
});
```
