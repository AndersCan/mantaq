title: Batch Creation
description: Create multiple states and events in one call.

`states()` and `events()`. Batch create. One call, typed record.

Checkout machine from [Actors](/mantaq/core-concepts/actors/). Its six states, its seven events — created in two calls.

## Without sugar

```ts
import { state, event } from "@mantaq/core";

const basicInfo = state("basicInfo")();
const shippingAddress = state("shippingAddress")();
const payment = state("payment")();
const submitting = state("submitting")();
const success = state("success")().final();
const error = state("error")();

const submitBasicInfo = event("submitBasicInfo")();
const submitShipping = event("submitShipping")();
const submitPayment = event("submitPayment")();
const back = event("back")();
const paymentOk = event("paymentOk")();
const paymentFail = event("paymentFail")();
const submittingDone = event("submittingDone")();
```

Thirteen calls. Repetitive.

## With sugar

```ts
import { states, events } from "@mantaq/sugar";

const { basicInfo, shippingAddress, payment, submitting, success, error } = states(
  "basicInfo",
  "shippingAddress",
  "payment",
  "submitting",
  { name: "success", final: true },
  "error",
);

const {
  submitBasicInfo,
  submitShipping,
  submitPayment,
  back,
  paymentOk,
  paymentFail,
  submittingDone,
} = events(
  "submitBasicInfo",
  "submitShipping",
  "submitPayment",
  "back",
  "paymentOk",
  "paymentFail",
  "submittingDone",
);
```

Two calls. Typed names as keys.

## Return type

`states()` returns a typed record keyed by the literal names — `{ [K in T]: StateRef<K> }`. Not a plain `Record<string, ...>`.

`events()` same shape for `EventRef`.

Keys are the names you passed. Dot or bracket access:

```ts
const s = states("basicInfo", "payment", "success");
s.basicInfo; // StateRef<"basicInfo">
s["payment"]; // StateRef<"payment">

const e = events("submitBasicInfo", "submitPayment");
e.submitBasicInfo; // EventRef<"submitBasicInfo">
```

Destructure or keep the record:

```ts
const s = states("basicInfo", "payment", "success");
const { basicInfo, payment, success } = s;
```

## Real example

Same checkout machine. Fewer lines.

```ts
import { Actor } from "@mantaq/core";
import { states, events } from "@mantaq/sugar";

const { basicInfo, payment, success } = states("basicInfo", "payment", {
  name: "success",
  final: true,
});
const { submitBasicInfo, submitPayment } = events("submitBasicInfo", "submitPayment");

const checkout = new Actor({
  inputs: [submitBasicInfo, submitPayment],
  states: [basicInfo, payment, success],
  initial: basicInfo,
  setup: (m) => {
    m.on(basicInfo, submitBasicInfo, () => ({ state: payment }));
    m.on(payment, submitPayment, () => ({ state: success }));
  },
});
```

## Type safety

```ts
const { basicInfo, success } = states("basicInfo", { name: "success", final: true });

// TypeScript knows:
basicInfo.name; // "basicInfo"
basicInfo.isFinal; // false
success.isFinal; // true
```

Finality is declared at creation — `{ name, final: true }`. No `.final()` call
to remember or discard. Names inferred as string literals.
