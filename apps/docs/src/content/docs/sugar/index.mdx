## What

`@mantaq/sugar` is an optional companion package. It wraps core primitives with
convenience helpers for the patterns every machine ends up repeating: batch
creation, state matching, effect timeouts, dynamic children.

## Why

Core is deliberately small and explicit. It shows what happens under the hood.
But the boilerplate adds up: thirteen `state(...)`/`event(...)` calls, a manual
abort check in every promise effect, hand-rolled path joins. Sugar cuts that
without hiding anything. Every helper compiles to the same behavior you could
write yourself. Sugar just saves the typing.

The sugar pages apply each helper to the checkout machine from
[Actors](/mantaq/core-concepts/actors/).

## What's inside

| Helper                                           | What                        |
| ------------------------------------------------ | --------------------------- |
| `states()`, `events()`                           | Batch create states/events  |
| `matches()`, `isIn()`, `activeLeaves()`, `tag()` | State matching and grouping |
| `ActorMap`, `broadcast()`                        | Dynamic child management    |
| `withPromise()`, `withTimeout()`                 | Effect helpers              |

## Install

```bash
npm install @mantaq/sugar
```

Needs `@mantaq/core` installed.

## Import

```ts
import { matches, states, events } from "@mantaq/sugar";
```

All exports come from one entry point.

## When to use

Use sugar when:

- Many states/events → `states()` saves lines
- Frequent state checks → `matches()` cleaner than path inspection
- Dynamic children → `ActorMap` handles registry
- Promises in effects → `withPromise()` bridges them

Skip sugar when:

- Few states/events
- Minimal state checks
- No dynamic children
- Custom effect patterns

## Philosophy

Sugar is not required. Core is sufficient for everything.

Sugar means less code for common patterns, nothing hidden. You could write every
helper yourself.
