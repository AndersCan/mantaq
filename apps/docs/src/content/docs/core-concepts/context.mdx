---
title: Context
description: Data that survives transitions.
---

Context. Holds data. Survives transitions. Replaced, not mutated.

## Define context

Pass object to Actor constructor.

```ts
type CounterContext = { count: number };

const actor = new Actor({
  inputs: [increment, decrement],
  states: [idle],
  initial: idle,
  context: { count: 0 } as CounterContext,
  setup: (m) => {
    m.on(idle, increment, (_event, { context }) => {
      const s = context.get();
      context.set({ ...s, count: s.count + 1 });
      return {};
    });
  },
});
```

`{} as CounterContext`. Type safety. No runtime cost.

## Read context

```ts
actor.context.count; // current value
```

## Context in transitions

Handlers get a `context` handle. `get()` reads the current value; `set()`
replaces it wholesale. A change is detected when the reference changes —
that is what triggers a `change` event.

```ts
setup: (m) => {
  m.on(idle, login, (event, { context }) => {
    const s = context.get();
    context.set({ ...s, username: event.username, attempts: s.attempts + 1 });
    return { state: authenticating };
  });
},
```

Nested values must be copied too — `set` only sees the top-level reference:

```ts
const s = context.get();
context.set({ ...s, items: [...s.items, item] });
```

## Context in effects

Effects get the same handle.

```ts
setup: (m) => {
  m.effect(authenticating, ({ context, emit }) => {
    const s = context.get();
    authenticate(s.username).then(
      (result) => emit({ id: "AUTH_DONE", result }),
    );
  });
},
```

## Context in children

Child actors. Own context. Communicate via events.

## Test context

```ts
const actor = createLoginActor();
actor.send(login.create({ username: "admin", password: "pass" }));
expect(actor.context.username).toBe("admin");
expect(actor.context.attempts).toBe(1);
```

Always read through `actor.context` — the value is replaced, not mutated, so a
reference you captured earlier goes stale.
