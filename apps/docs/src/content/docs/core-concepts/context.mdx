title: Context
description: Data that survives transitions.
---

## What

Context is the actor's data — a record you define, pass in at construction, and
read and replace while the machine runs.

## Why

A flow accumulates data. The buyer enters their email, then their address, then
their payment details, and all of it needs to be around at the end when the
card is charged. Context is that place: it survives transitions, so each step
can add to what the previous steps collected.

Context is not state. It doesn't decide where the machine is — the state does.
And it is replaced, not mutated: `set()` swaps the whole record, so a reference
you captured earlier goes stale.

The checkout machine from [Actors](/mantaq/core-concepts/actors/). Context
holds the form data as the buyer moves through the steps.

## Define context

Pass an object to the Actor constructor.

```ts
type BasicInfo = { email: string; name: string };
type ShippingAddress = { street: string; city: string; zip: string };
type PaymentInfo = { cardNumber: string };

type CheckoutContext = {
  basicInfo?: BasicInfo;
  shippingAddress?: ShippingAddress;
  paymentInfo?: PaymentInfo;
  orderId?: string;
};

const checkout = new Actor({
  // ...
  context: {} as CheckoutContext,
  setup: (m) => {
    /* ... */
  },
});
```

It's typed — the shape is known from the start, with no runtime cost.

## Context in transitions

Handlers get a `context` handle. `get()` reads the current value; `set()`
replaces it wholesale. Any `set()` call triggers a `change` event — even if you
set the same reference. Copy the current value to mutate.

```ts
m.on(basicInfo, submitBasicInfo, (event, { context }) => {
  const s = context.get();
  context.set({ ...s, basicInfo: { ...event.payload } });
  return { state: shippingAddress };
});
```

Each step adds one field. Earlier fields survive — context carries across
transitions.

Nested values must be copied too — `set` only sees the top-level reference:

```ts
const s = context.get();
context.set({ ...s, items: [...s.items, item] });
```

## Read context

```ts
checkout.context.basicInfo?.email; // current value
```

Always read through `actor.context`. The value is replaced, not mutated, so a
reference you captured earlier goes stale.

## Context in effects

Effects get the same handle. The charge effect reads the payment info and
writes the order id on success.

```ts
setup: (m) => {
  m.effect(submitting, ({ context, emit }) => {
    const s = context.get();
    chargeCard(s.paymentInfo!.cardNumber).then((orderId) => {
      const cur = context.get();
      context.set({ ...cur, orderId });
      emit(paymentOk.create({ orderId }));
    });
  });
};
```

## Context in children

Child actors (regions) have their own context and communicate via events. See
[States](/mantaq/core-concepts/states/).

## Test context

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.context.basicInfo; // { email: "a@b.com", name: "A" }
checkout.context.shippingAddress; // undefined

checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
checkout.context.shippingAddress; // { street: "1 Main", city: "Oslo", zip: "0150" }
```

It accumulates, step by step.
