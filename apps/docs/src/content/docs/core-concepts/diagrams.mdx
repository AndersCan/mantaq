## What

Every `m.on` and `m.onAny` lists its targets in `to`. The builder records them,
so the whole transition graph is static data: it can be drawn without running
a single handler.

The diagram below is the docs' checkout machine
([`checkout.ts`](https://github.com/anderscan/mantaq/blob/main/apps/docs/src/content/docs/checkout.ts)),
generated when the site is built. It cannot drift from the code.

## Reading it

- **Box**: a state. Double border: final.
- **Arrow**: one target from one `to` list, labelled with its event.
- **Dot and arrow on the left**: the initial state.
- **Dotted arrow, italic label**: an internal event, emitted by an effect.
- **Faint self-loop**: the effects the state runs on entry, by name (`runs chargeCard`).
- **Dashed box `*`**: an `onAny` registration, meaning any non-final state.

Click a state or an edge, or focus it and press Enter. The panel shows the
handler behind an edge: where it is registered, which branches lead where,
and what it reads and writes in context.

## Walking it

The diagram starts in the initial state. Pulsing edges are the steps you can
take next. Click one, click the state it leads to, or use the buttons in the
panel. The panel groups the next steps:

- **Send an input**: what a user or caller can send.
- **Effect reports back**: the events an effect of this state declares in
  `sends`. Entering `submitting` runs `chargeCard`, which sends `paymentOk`,
  `paymentFail` or `paymentTimeout`. Pick one to say how the charge went.
- **Other internal events**: internal events that no effect of this state
  declares.

Nothing runs: the walk follows the drawn edges, so no network or service is
needed. **Back**, **Reset** and the path list undo steps. The standalone viewer
keeps the walk in the URL (`?step=`), so a link opens the same path.

## What it does not tell you

Guards are not evaluated. An edge means the handler _may_ go there, not that it
ever will. A handler with no `to` can only stay in place.

When the target depends on the current state, register one `m.on` per state
instead of branching on `actor.state` inside `onAny`. Each `back` above is its
own edge for that reason. See [`onAny`](/mantaq/core-concepts/events/#onany).
