## What

An effect is a function that runs every time the actor enters a state. It does
side-effect work and emits events back into the machine. It does not transition
the machine directly.

## EffectInput

```ts
{
  signal: AbortSignal;
  state: { name: string; payload: unknown };
  event: InternalEvent;
  context: Context<ActorContext>;
  emit: (event) => void;
  clock: Clock;
}
```

## Rules

- Run on every entry, initial state included (`event.type` is `"__init"` at construction)
- Terminal states run entry effects too (emit completion outputs to parents)
- Return value is ignored. Effects emit; the machine reacts.
- Never throw. Catch and emit an internal error event instead.

## Auto-abort

`signal` fires when the actor leaves the state. Check it before emitting.

The examples below are `m.effect` calls from the `setup` of the docs [checkout machine](https://github.com/anderscan/mantaq/blob/main/apps/docs/src/content/docs/checkout.ts), where `chargeCard`, `submitting` and the payment events are declared.

```ts
m.effect(submitting, {
  name: "chargeCard",
  fn: ({ signal, emit, context }) => {
    const cardNumber = context.get().paymentInfo?.cardNumber ?? "";
    chargeCard(cardNumber).then((orderId) => {
      if (!signal.aborted) emit(paymentOk.create({ orderId }));
    });
  },
});
```

Post-abort `emit` is a silent no-op anyway. The guard skips the wasted call.

## Declaring what an effect sends

List the internal events an effect can emit in `sends`. `emit` then accepts
only those events. Emitting anything else is a type error.

```ts
m.effect(submitting, {
  name: "chargeCard",
  sends: [paymentOk, paymentFail, paymentTimeout],
  fn: ({ signal, emit, context }) => {
    const cardNumber = context.get().paymentInfo?.cardNumber ?? "";
    chargeCard(cardNumber).then((orderId) => {
      if (!signal.aborted) emit(paymentOk.create({ orderId }));
    });
  },
});
```

- `sends: []`: the effect emits nothing.
- No `sends`: `emit` takes any event, untyped. This exists for migration only.
- `sends` lists internal events only. Inputs come from outside.

The diagram uses `sends` to show which events can follow an effect. Walking
the [diagram](/mantaq/core-concepts/diagrams/), entering `submitting` offers
`paymentOk`, `paymentFail` and `paymentTimeout` as next steps.

## Multiple effects

Call `m.effect` multiple times for one state. They run in order.

```ts
m.effect(submitting, {
  name: "chargeCard",
  sends: [paymentOk, paymentFail],
  fn: ({ signal, emit, context }) => {
    const cardNumber = context.get().paymentInfo?.cardNumber ?? "";
    chargeCard(cardNumber).then(
      (id) => {
        if (!signal.aborted) emit(paymentOk.create({ orderId: id }));
      },
      (err) => {
        if (!signal.aborted) emit(paymentFail.create({ reason: String(err) }));
      },
    );
  },
});
m.effect(submitting, {
  name: "startSubmitTimeout",
  sends: [paymentTimeout],
  fn: ({ signal, emit, clock }) => {
    clock.setTimeout(800, { signal, cb: () => emit(paymentTimeout.create()) });
  },
});
```

## Error handling

An uncaught error moves the actor to the built-in terminal `__error` state.
`snapshot().done` becomes `true`, `snapshot().error` carries the failure. The
actor stops accepting events.
