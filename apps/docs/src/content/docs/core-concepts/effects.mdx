Effect. Runs on state entry. Gets `EffectInput`. Can emit events.

Register effects in `setup` with `m.effect(state, fn)`.

Checkout machine from [Actors](/mantaq/core-concepts/actors/). Its `submitting`
state needs two things: charge the card, and bail out if it takes too long.
Both are effects.

## Basic effect

The `submitting` effect. Entry starts the charge. `emit` carries the result
back to the machine as internal events.

```ts
setup: (m) => {
  m.effect(submitting, (input) => {
    const s = input.context.get();
    chargeCard(s.paymentInfo!.cardNumber).then(
      (orderId) => input.emit(paymentOk.create({ orderId })),
      (reason) => input.emit(paymentFail.create({ reason: String(reason) })),
    );
  });
};
```

`chargeCard` is your payment provider. A promise. Resolves → `paymentOk` →
`submitting` transitions to `success`. Rejects → `paymentFail` → `error`.

Effect return value ignored. Effect emits. Machine reacts.

## EffectInput

```ts
{
  signal: AbortSignal;           // abort on state exit
  state: { name: string; payload: unknown };  // payload typed from state ref
  event: InternalEvent;  // trigger event (`{ type: "__init" }` at construction)
  context: Context<ActorContext>; // handle: get() reads, set() replaces
  emit: (event) => void;        // emit event: internal, input, or output
  clock: Clock;                 // timers
}
```

Effects run on every state entry — the initial state included. An effect on the
initial state fires at construction, armed like any other entry. Its `event` is
the synthetic `{ type: "__init" }`. Terminal states run their entry effects too,
so a final state can `emit` a completion output to a parent.

## Auto-abort

Effect aborts. Actor leaves state. The `signal` fires. In-flight promises must
check it before emitting.

```ts
setup: (m) => {
  m.effect(submitting, ({ signal, emit }) => {
    chargeCard(s.paymentInfo!.cardNumber).then((orderId) => {
      if (!signal.aborted) emit(paymentOk.create({ orderId }));
    });
  });
};
```

No manual cleanup. AbortSignal handles it. Charge returns after user backed
out → no emit. The guard is belt-and-braces: an `emit` called after abort is a
silent no-op anyway — the guard just skips the wasted call.

## Multiple effects

Call `m.effect` multiple times for the same state. Runs in order.

```ts
setup: (m) => {
  m.effect(submitting, ({ signal }) => {
    /* charge */
  });
  m.effect(submitting, (input) => {
    // fallback: if charge hangs, time out
    input.clock.setTimeout(800, () => {
      if (!input.signal.aborted) input.emit(submittingDone.create());
    });
  });
};
```

`submittingDone` transitions to `success` — the timeout fallback. See [Effect Helpers](/mantaq/sugar/effect-helpers/) for the sugar version of both patterns.

## Error handling

Never throw in an effect. Catch and emit an internal error event; a transition
handles it. `paymentFail` lands the machine in `error` — the transition already
exists.

An uncaught error still can't crash `send()`. The actor transitions to the
built-in terminal `__error` state, and the thrown value lands in
`snapshot().error`. `__error` is final — `snapshot().done` is `true` and the
`"done"` event fires, so a parent or `ActorMap` can reap a died child.

```ts
setup: (m) => {
  m.effect(submitting, ({ signal, emit }) => {
    chargeCard(s.paymentInfo!.cardNumber)
      .then((orderId) => {
        if (!signal.aborted) emit(paymentOk.create({ orderId }));
      })
      .catch((reason) => {
        if (!signal.aborted) emit(paymentFail.create({ reason: String(reason) }));
      });
  });
};
```
