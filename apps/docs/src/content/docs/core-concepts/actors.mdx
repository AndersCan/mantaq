## What

An Actor is one running state machine instance. It owns everything the machine
needs: the current state, the mutable context, the registered transitions and
effects, the clock, and any child actors.

## Why

States, events, and effects are declarations until an Actor runs them. The
Actor is what makes the machine live — it accepts events, applies transitions,
runs effects, and reports what it is doing. When you test a flow, you test an
Actor.

It's not a class you subclass per state. One Actor per flow, with its
transitions and effects registered together in `setup`.

The checkout form from [Introduction](/mantaq/getting-started/introduction/)
is now full: all six states, all seven events.

## Make an actor

Transitions and effects are registered in a `setup` callback. The builder is
type-safe: a target state or event you didn't declare won't compile.

```ts
import { Actor, state, event } from "@mantaq/core";

type BasicInfo = { email: string; name: string };
type ShippingAddress = { street: string; city: string; zip: string };
type PaymentInfo = { cardNumber: string };

type CheckoutContext = {
  basicInfo?: BasicInfo;
  shippingAddress?: ShippingAddress;
  paymentInfo?: PaymentInfo;
  orderId?: string;
};

const basicInfo = state("basicInfo")();
const shippingAddress = state("shippingAddress")();
const payment = state("payment")();
const submitting = state("submitting")();
const success = state("success")().final();
const error = state("error")();

const submitBasicInfo = event("submitBasicInfo")<BasicInfo>();
const submitShipping = event("submitShipping")<ShippingAddress>();
const submitPayment = event("submitPayment")<PaymentInfo>();
const back = event("back")();
const paymentOk = event("paymentOk")<{ orderId: string }>();
const paymentFail = event("paymentFail")<{ reason: string }>();
const submittingDone = event("submittingDone")();

const checkout = new Actor({
  inputs: [submitBasicInfo, submitShipping, submitPayment, back],
  internal: [paymentOk, paymentFail, submittingDone],
  states: [basicInfo, shippingAddress, payment, submitting, success, error],
  initial: basicInfo,
  context: {} as CheckoutContext,
  setup: (m) => {
    m.on(basicInfo, submitBasicInfo, (event, { context }) => {
      const s = context.get();
      s.basicInfo = event.payload;
      context.set(s);
      return { state: shippingAddress };
    });
    m.on(shippingAddress, submitShipping, (event, { context }) => {
      const s = context.get();
      s.shippingAddress = event.payload;
      context.set(s);
      return { state: payment };
    });
    m.on(payment, submitPayment, (event, { context }) => {
      const s = context.get();
      s.paymentInfo = event.payload;
      context.set(s);
      return { state: submitting };
    });
    m.on(submitting, paymentOk, (event, { context }) => {
      const s = context.get();
      s.orderId = event.payload.orderId;
      context.set(s);
      return { state: success };
    });
    m.on(submitting, paymentFail, () => ({ state: error }));
    m.on(submitting, submittingDone, () => ({ state: success }));
    m.onAny(back, (_event, { context }) => {
      const s = checkout.state.name;
      if (s === "payment") {
        const cur = context.get();
        cur.paymentInfo = undefined;
        context.set(cur);
        return { state: shippingAddress };
      }
      if (s === "shippingAddress") {
        const cur = context.get();
        cur.shippingAddress = undefined;
        context.set(cur);
        return { state: basicInfo };
      }
      if (s === "error") return { state: payment };
      return {};
    });
  },
});
```

The flow:

```
basicInfo → shippingAddress → payment → submitting → success
                  ↕ (back) ↕                   ↕ (back)
                                            error
```

`back` is handled in every state with `onAny`. A state-specific handler runs
first; `onAny` only transitions if no state handler fired.

Note that nothing emits `paymentOk` yet. Effects do that — the
[Effects page](/mantaq/core-concepts/effects/) adds them.

## Send events

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
```

`.create()` builds the event you send. Events with a payload need the payload
argument.

## Check the state

```ts
checkout.snapshot().path[0]; // "payment"
```

For cleaner checks, `@mantaq/sugar` has `matches(checkout, "payment")`. See
[Matching](/mantaq/sugar/matching/).

## Listen for changes

```ts
const unsub = checkout.on("change", (snapshot) => {
  console.log("New state:", snapshot.path);
});

// Call unsub() to stop
```

The handler fires immediately with the current snapshot, then on every state
or context change.

## Settled

```ts
await checkout.settled();
```

Waits until internal events are drained and pending effects are done. Use it
after effects before asserting.

## Snapshot

```ts
checkout.snapshot();
// { path: ["payment"], context: {...}, regions: {} }
```

The full state tree. It nests for actors with children.

## Constructor options

| Option           | Type                                | What                                 |
| ---------------- | ----------------------------------- | ------------------------------------ |
| `inputs`         | `EventRef[]`                        | External events accepted             |
| `outputs`        | `EventRef[]`                        | Events to parent                     |
| `internal`       | `EventRef[]`                        | Events from effects/transitions      |
| `states`         | `StateRef[]`                        | All states                           |
| `initial`        | `StateRef` or `{ state, payload? }` | Start state                          |
| `context`        | `ActorContext`                      | Initial context                      |
| `clock`          | `Clock`                             | Default: `RealClock`                 |
| `setup`          | `(m: ActorBuilder) => void`         | Register transitions and effects     |
| `regions`        | `Record<string, AnyActor>`          | Static children                      |
| `internalBudget` | `number`                            | Max internal events (default: 10000) |

### `setup` builder

| Method                   | What                                        |
| ------------------------ | ------------------------------------------- |
| `m.on(state, event, fn)` | Transition handler for one state/event pair |
| `m.onAny(event, fn)`     | Handler for an event in every state         |
| `m.effect(state, fn)`    | Run `fn` on state entry                     |

A handler returns `{ state }` (optionally with `payload`, or `emit:
[{ type }]`) to transition, or `{}` to stay in place.
