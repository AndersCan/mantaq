## What

The visualizer draws a machine as a graph and lets you walk it. States are nodes, transitions are edges.

## Why

Reading handlers shows what one state does. The graph shows every path, and walking it shows which step you can take next. The visualizer reads a viz document made from your machine; it does not run your handlers unless you use the live page.

### Walking the graph

The viewer keeps a cursor on one state, starting at the initial one. Moving accent arrows are the steps the walk can take next. A click on a state selects it and shows it in Details. A click on an arrow that leaves the state the walk is in sends its event, also when a lock shows that its guard blocks it. A click on any other arrow opens Details with one line that says why it can't be sent. The `?` beside an arrow's label opens its Details without sending. The **Context** tab shows the actor's context as the walk changes it. Without a live run it lists the context fields that the machine declares. **Full screen**, above the diagram, fills the screen with the viewer; Escape returns. Browsers without element full screen (iPhone Safari) show no button.

In an actor map the diagram shows the child machine once. Live, each child is a chip with its key on the state it is in, and the Step tab lists every child with its state. Click a chip or a row to follow that child: its row is marked, and a click on an arrow in the map sends to it.

The selected arrow's Details has a send form when a click on the arrow sends: one box per payload field and a **Send** button. The boxes hold the values that a click sends: the values last sent, else the examples. A change stays for every later send of that event. The lock on a blocked arrow is worked out with the same values. If the arrow can't be sent, one line says why. After a send, Details say what was sent, with its values, and where it went. Links keep the changed values in `?payload=`, and old `?value=` links still open with their values. An arrow responds wherever its line is clicked, dashed and dotted ones included.

Effects do not run on the live page: the answers of `submitting` (`paymentOk`, `paymentFail`, `paymentTimeout`) are the arrows out of it. The initial state's effects run while the machine is built.

A final state ends the walk. **Back** and **Reset** undo steps. `?machine=checkout&run=<name>` opens a recorded run by name; use it for links in docs and issues.

On the live page (the Vite plugin) each step runs the real actor, so guards are evaluated.

A state that embeds another machine shows the id of that machine and an **enter** control. Enter draws the embedded machine on its own, without the walk. The walk and its steps stay as they were. The path above the diagram names each machine you opened. Click a name to go back to that machine, or press Escape to go back one. `?focus=` keeps the path in the address bar, so a link opens the same machine.

### Nodes

| Style                                                              | Meaning                                                                                       |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Box                                                                | A state                                                                                       |
| Double border                                                      | A final state                                                                                 |
| Thick border                                                       | The state the walk is on                                                                      |
| Dot and arrow on the left                                          | The initial state                                                                             |
| Dashed box `any state`                                             | An `onAny` registration, or an event every non-final state leaves by the same arrows          |
| Dashed box with a count (`5 states`)                               | An event those states leave by the same arrows, drawn once; its arrow's Details list them all |
| Pill inside a state                                                | An effect the state runs on entry, by name (`chargeCard` in `submitting`)                     |
| Dashed circle `?`                                                  | An unknown target                                                                             |
| Shaded rectangle                                                   | A region: its own start arrow and current state                                               |
| Box titled with the map's name                                     | An actor map: its child machine drawn once, each live child a chip                            |
| `3 waiting` and outlined pills at the bottom of a pool's own state | The items waiting in a `createPool` inbox, the next one on the left; `+N` more past the edge  |
| Dark chip with a key at the bottom of a state                      | A live child of an actor map, by key                                                          |

### Edges

| Style               | Meaning                                            |
| ------------------- | -------------------------------------------------- |
| Solid arrow         | A transition on an input event                     |
| Dotted arrow        | A transition on an internal event                  |
| Dotted self-loop    | The event is handled and the state does not change |
| Dashed orange arrow | Undetermined target                                |
| Moving accent arrow | A step the walk can take next                      |
| Teal arrow          | The arrow last clicked or shown in Details         |
| `?` beside a label  | Opens that arrow's Details                         |
