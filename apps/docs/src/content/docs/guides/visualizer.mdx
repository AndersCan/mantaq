## What

The visualizer draws a machine as a graph and lets you walk it. States are nodes, transitions are edges.

## Why

Reading handlers shows what one state does. The graph shows every path, and walking it shows which step you can take next. The visualizer reads a viz document made from your machine; it does not run your handlers unless you use the live page.

### Walking the graph

The viewer keeps a cursor on one state, starting at the initial one. Moving accent arrows are the steps the walk can take next. When the panel is shown, a click on a state selects it and shows it in Details. An arrow is a button only while a click on it sends its event and moves the walk. A click on any other arrow does nothing. Its hover title says why it can't be sent, and so do its Details. An arrow that a guard blocks keeps its lock. The `?` beside an arrow's label opens its Details without sending. The **Context** tab shows the actor's context as the walk changes it. Without a live run it lists the context fields that the machine declares. **Full screen**, above the diagram, fills the screen with the viewer; Escape returns. Browsers without element full screen (iPhone Safari) show no button.

In an actor map the diagram shows the child machine once. Live, each child is a chip with its key on the state it is in, and the Step tab lists every child with its state. Click a chip or a row to follow that child: its row is marked, and a click on an arrow in the map that the child can take sends to it.

The selected arrow's Details has a send form when the arrow leaves the state the walk is in, also when a guard blocks it: one box per payload field and a **Send** button. The boxes hold the values that a click sends: the values last sent, else the examples. A change stays for every later send of that event. The lock on a blocked arrow is worked out with the same values. If the arrow can't be sent, one line says why. After a send, Details say what was sent, with its values, and where it went. Links keep the changed values in `?payload=`, and old `?value=` links still open with their values. An arrow responds wherever its line is clicked, dashed and dotted ones included.

Effects do not run on the live page: the answers of `submitting` (`paymentOk`, `paymentFail`, `paymentTimeout`) are the arrows out of it. The initial state's effects run while the machine is built.

A final state ends the walk. **Back** and **Reset** undo steps. `?machine=checkout&run=<name>` opens a recorded run by name; use it for links in docs and issues.

On the live page (the Vite plugin) each step runs the real actor, so guards are evaluated.

### Moving around

The viewer can draw a machine at more than one level. When you open a machine on a board or enter a group, a path above the canvas shows the level that it draws now. The path starts with the name of the machine, and each level in adds one name, for example `order › payment`.

- Board: if `create` returns two or more other machines next to its actor, the viewer first draws a board. A board has one box per machine, and a dotted line between two machines that send messages to each other. Click a box to open that machine. Its name is added to the path.
- Group: if states of the machine have a `@group` tag, the viewer draws each group as one node. Click `enter` on a group node to draw the states of that group. Its name is added to the path. [Group the states of a big machine](/mantaq/guides/group-states/) shows this on a live diagram.
- Path: click a name in the path to go back to that level. Press Escape to go back one level. The last name is the level that the canvas draws, and a click on it does nothing.

A move along the path does not change the walk or the Step log. An arrow from the state that the walk is in sends at every level, because the machine has one walk. Inside a group, a dashed box is a state outside the group. Click it to go back one level and show that state there.

The address keeps the path in `?focus=`: the name of a machine on a board, then the id of a group node, such as `@payment`. A link with `?focus=` opens the same level. For example, `?machine=order&focus=@payment` opens the group `payment` of the machine `order`. Repeat `focus` for each level: `?focus=till&focus=@payment` opens the machine `till` of a board, then its group `payment`.

### Navigation

The viewer opens with the diagram as wide as the canvas, but its labels never get smaller than a set size. A wider diagram scrolls sideways. You can zoom and pan the canvas. The zoom and the tool stay the same after a step, after a move along the path and after a resize, until you reload the page.

| Gesture or key                                | What it does                                                            |
| --------------------------------------------- | ----------------------------------------------------------------------- |
| Ctrl or Cmd and the mouse wheel               | Zooms in or out at the pointer                                          |
| Pinch on a trackpad                           | Zooms in or out at the pointer                                          |
| Mouse wheel, or Shift and the mouse wheel     | Scrolls, as on any page                                                 |
| Click in the viewer, then hold Space and drag | Pans the canvas                                                         |
| Drag with the middle mouse button             | Pans the canvas                                                         |
| Ctrl or Cmd and `+` or `=`                    | Zooms in one step                                                       |
| Ctrl or Cmd and `-`                           | Zooms out one step                                                      |
| Shift+1                                       | Zooms so that the whole diagram fits                                    |
| Shift+0                                       | Zooms to 100%, the natural size of the diagram                          |
| H                                             | Hand tool: a drag anywhere on the canvas pans, and a click does nothing |
| V                                             | Select tool: a click on a state or an arrow acts again                  |

The keys work while focus is in the viewer and not in a text field. They also work after you click in the viewer or zoom it, while nothing else has focus. Space pans only while the pointer is over the canvas. Space still presses a button outside the diagram that has focus. While the pointer is over the canvas, Space pans even when a state or an arrow has focus, and Enter presses it, also in the Hand tool.

### Nodes

| Style                                                              | Meaning                                                                                       |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Box                                                                | A state                                                                                       |
| Double border                                                      | A final state                                                                                 |
| Thick border                                                       | The state the walk is on                                                                      |
| Dot and arrow into a state (from the left, or from above)          | The initial state                                                                             |
| Dashed box `any state`                                             | An `onAny` registration, or an event every non-final state leaves by the same arrows          |
| Dashed box with a count (`5 states`)                               | An event those states leave by the same arrows, drawn once; its arrow's Details list them all |
| Pill inside a state                                                | An effect the state runs on entry, by name (`chargeCard` in `submitting`)                     |
| Dashed circle `?`                                                  | An unknown target                                                                             |
| Shaded rectangle                                                   | A region: its own start arrow and current state                                               |
| Box titled with the map's name                                     | An actor map: its child machine drawn once, each live child a chip                            |
| Box with a box-in-a-box mark and `enter`                           | A group: its states drawn as one node, with the count of its states or `now in <state>`       |
| Dashed box while a group is entered                                | A state outside the group. A click on it goes back one level and shows it there               |
| Box with a machine's name on a board                               | One machine of the board. A click on it opens that machine                                    |
| `3 waiting` and outlined pills at the bottom of a pool's own state | The items waiting in a `createPool` inbox, the next one on the left; `+N` more past the edge  |
| Dark chip with a key at the bottom of a state                      | A live child of an actor map, by key                                                          |

### Edges

| Style               | Meaning                                                              |
| ------------------- | -------------------------------------------------------------------- |
| Solid arrow         | A transition on an input event                                       |
| Dotted arrow        | A transition on an internal event                                    |
| Dotted self-loop    | The event is handled and the state does not change                   |
| Dashed orange arrow | Undetermined target                                                  |
| Moving accent arrow | A step the walk can take next                                        |
| Still accent arrow  | A next step that another part sends, not a click                     |
| Teal arrow          | The arrow last clicked, or shown in Details unless a guard blocks it |
| `?` beside a label  | Opens that arrow's Details                                           |
