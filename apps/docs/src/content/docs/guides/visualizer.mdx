---
title: How the visualizer works
description: Walking a machine's graph in the viewer, and what each node and edge style means.
---

The visualizer draws a machine as a graph and lets you walk it. States are nodes, transitions are edges. It reads a viz document made from your machine; it does not run your handlers unless you use the live page.

## Walking the graph

The viewer keeps a cursor on one state, starting at the initial one. Pulsing edges are the steps you can take next. Take one by:

- clicking a pulsing edge,
- clicking a state that exactly one next step reaches,
- using a button in the panel.

In an actor map an arrow goes to the child you picked (click its pill), else to the child that started first.

The panel groups the next steps:

- **Send an input**: edges on input events.
- **Effect reports back**: internal events that an effect of the current state declares in `sends`.
- **Other internal events**: internal events that no effect of the state declares.

On the live page those events are the arrows you click. Effects do not run there: `submitting` shows `waiting for chargeCard`, and its answers (`paymentOk`, `paymentFail`, `paymentTimeout`) are the arrows out of it. Every event and the clock are also under **Events and time**. The initial state's effects run while the machine is built.

A final state ends the walk. **Back** (or the left arrow), **Reset** and the path list undo steps. The standalone page keeps the walk in the URL (`?step=`), so a link opens the same path. `?machine=checkout&run=<name>` opens a recorded run by name; use it for links in docs and issues.

A static walk follows declarations: guards are not evaluated, so a path may not happen at runtime. On the live page (the Vite plugin), each step runs the real actor, so guards are evaluated.

An edge with an unknown target (dashed, orange) offers each target its handler explanation names. Without an explanation it cannot be taken.

## Nodes

| Style                      | Meaning                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Box                        | A state                                                                                                                     |
| Double border              | A final state                                                                                                               |
| Thick border               | The state the walk is on                                                                                                    |
| Dot and arrow on the left  | The initial state                                                                                                           |
| Dashed box `*`             | An `onAny` registration: any non-final state                                                                                |
| Dashed circle `?`          | An unknown target                                                                                                           |
| Shaded rectangle           | A region: its own start arrow and current state                                                                             |
| Box labelled "one per key" | An actor map: its graph is drawn once for every child                                                                       |
| Pill with a key (`p1`)     | One child of an actor map, on the state it is in; outlined when finished; dots and a count when a state holds more than fit |

## Edges

| Style                      | Meaning                                            |
| -------------------------- | -------------------------------------------------- |
| Solid arrow                | A transition on an input event                     |
| Dotted arrow, italic label | A transition on an internal event                  |
| Dotted self-loop           | The event is handled and the state does not change |
| Faint self-loop            | Effects the state runs on entry, by name           |
| Dashed orange arrow        | Undetermined target                                |
| Green arrow                | Seen only while fuzzing, not declared              |
| Pulsing dashed arrow       | A step you can take next                           |

## Coverage

The **Coverage from** picker dims elements with zero hits. With example tests, dimmed means no test exercises it. With fuzz runs, dimmed usually means a declared edge that no run reached, often because its guards never allow it. Fuzzing is not proof, so check the handler.

Click a state or an edge to see its handler in the panel: where it is registered, which branches lead where, and what it reads and writes in context.
