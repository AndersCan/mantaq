---
title: Property-Based Testing
description: Prove checkout-machine invariants across generated inputs instead of single examples.
---

Property tests assert an invariant over every generated input, not one path.

## The runner

`runProperty(arb, predicate)` generates values, feeds each to the predicate, fails on first `false`. Import from `@mantaq/pbt`.

- `fc` is fast-check's full API. `@mantaq/pbt` adds: `anyDuration`, `anySmallDuration`, `anyPayload`, `anyName`, `anyActorSnapshot`.
- `MANTAQ_SEED` env var overrides the fixed default seed. Default `numRuns`: 100.

## Deadline-exactness invariant

Machine in `submitting` schedules `paymentTimeout` after `timeoutMs`. `VirtualClock.advance(ms)` is synchronous, fires timers, drains queue.

```ts
import { Actor, VirtualClock } from "@mantaq/core";
import { fc, runProperty } from "@mantaq/pbt";
import {
  back,
  basicInfo,
  error,
  payment,
  paymentTimeout,
  shippingAddress,
  submitBasicInfo,
  submitShipping,
  submitting,
  success,
} from "./checkout";

runProperty(
  fc.tuple(fc.integer({ min: 0, max: 1000 }), fc.integer({ min: 0, max: 1000 })),
  ([timeoutMs, advanceMs]) => {
    const clock = VirtualClock();
    const actor = Actor({
      clock,
      inputs: [],
      internal: [paymentTimeout],
      states: [basicInfo, shippingAddress, payment, submitting, success, error],
      initial: submitting,
      setup: (m) => {
        m.on(submitting, { event: paymentTimeout, to: [error], handler: () => ({ state: error }) });
        m.effect(submitting, {
          name: "startSubmitTimeout",
          fn: ({ signal, clock: c, emit }) => {
            c.setTimeout(timeoutMs, { signal, cb: () => emit(paymentTimeout.create()) });
          },
        });
      },
    });
    clock.advance(advanceMs);
    const timedOut = actor.snapshot().path[0] === "error";
    return advanceMs >= timeoutMs ? timedOut : !timedOut;
  },
);
```

`internal: [paymentTimeout]` marks it machine-internal so external sends cannot fake the deadline.

## Back-navigation invariant

From any pre-payment step, mashing `back` never reaches a final state.

```ts
runProperty(fc.integer({ min: 0, max: 10 }), (presses) => {
  const actor = Actor({
    inputs: [back, submitBasicInfo, submitShipping],
    states: [basicInfo, shippingAddress, payment, success, error],
    initial: basicInfo,
    setup: (m) => {
      m.on(basicInfo, {
        event: submitBasicInfo,
        to: [shippingAddress],
        handler: () => ({ state: shippingAddress }),
      });
      m.on(shippingAddress, {
        event: back,
        to: [basicInfo],
        handler: () => ({ state: basicInfo }),
      });
      m.on(shippingAddress, {
        event: submitShipping,
        to: [payment],
        handler: () => ({ state: payment }),
      });
      m.on(payment, {
        event: back,
        to: [shippingAddress],
        handler: () => ({ state: shippingAddress }),
      });
    },
  });

  for (let i = 0; i < presses; i++) {
    const current = actor.snapshot().path[0];
    actor.send(back.create());
    if (actor.snapshot().path[0] === "payment") return false;
    if (current === "basicInfo" && actor.snapshot().path[0] !== "basicInfo") return false;
  }
  return actor.snapshot().done !== true;
});
```

## Seeding and CI

- Default seed is fixed. CI runs are deterministic, failures reproducible.
- Set `MANTAQ_SEED=<n>` to explore new input regions or replay a counterexample.
