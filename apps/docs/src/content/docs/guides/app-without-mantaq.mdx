## What

Check an app that has no mantaq in it against a state machine you wrote as its model.

## Why

The app's tests pass or fail on its own examples. A model walked at random finds sequences nobody wrote, and the failure comes with the shortest one.

### Events with data

An event with data needs sample payloads; walks pick among them.

```ts
payloads: { setCount: [{ count: 0 }, { count: 3 }] },
```

### Async apps

Adapters may return promises. Write an async result the app waits for as a model event: the adapter makes it happen, then awaits the app. Pass a timeout to `test` for slow apps.

```ts
save: (app) => { app.save(); },
saveFinished: async (app) => { backend.finish(); await app.saving; },
```

### Test a web page

Ask a coding agent to model one feature of a page and check the real page against it in Playwright. Try it on the sample sign-up page:

```bash
npx degit AndersCan/mantaq/apps/docs/src/conform/signup-page signup-page
cd signup-page
npm install
npx playwright install chromium
npx skills add AndersCan/mantaq -y
```

Then paste this to your agent:

<Code code={ask} lang="text" title="The ask" wrap />

The agent writes two files, `signup-model.ts` and `signup.spec.ts`, and `npx playwright test` prints `1 passed`. That means 100 walks of up to 30 actions, with the page and the model compared after each, and every arrow in the model taken. A model with one or two states proves little.

Now break the email check: in `index.html` change `!EMAIL.test(email)` to `!email.includes("@")` and run again. The test fails with the shortest actions that reach it. With our model of the form it prints:

<Code code={signupFailure} lang="text" />

Read the rows as what a person did: typed `ada@example`, pressed Sign up. The page showed the password problem where the model expected the email problem. If the app column did not move on an action's first row, check the adapter's locator before the page. Change the line back and it passes.
