## What

Testing an actor means driving it with events and asserting where it lands. The
machine is a graph: states are nodes, transitions are edges. A test is a
walk through that graph.

## Why

Mantaq is deterministic: same inputs, same trace, every time. That makes flows
assertable without flakiness: no sleeps, no "wait 100ms and hope". Time-based
transitions run on a `VirtualClock`, so you fast-forward instead of waiting.

The checkout machine from [Context](/mantaq/core-concepts/context/). Full flow:

```
basicInfo → shippingAddress → payment → submitting → success (final)
                  ↕ (back) ↕                  ↕ (back)
                                            error
```

## The machine

```ts
import { Actor, VirtualClock, state, event } from "@mantaq/core";

type CheckoutContext = {
  basicInfo?: { email: string; name: string };
  shippingAddress?: { street: string; city: string; zip: string };
  paymentInfo?: { cardNumber: string };
  orderId?: string;
};

const basicInfo = state("basicInfo")();
const shippingAddress = state("shippingAddress")();
const payment = state("payment")();
const submitting = state("submitting")();
const success = state("success")().final();
const error = state("error")();

const submitBasicInfo = event("submitBasicInfo")<{
  email: string;
  name: string;
}>();
const submitShipping = event("submitShipping")<{
  street: string;
  city: string;
  zip: string;
}>();
const submitPayment = event("submitPayment")<{ cardNumber: string }>();
const back = event("back")();
const paymentOk = event("paymentOk")<{ orderId: string }>();
const paymentFail = event("paymentFail")<{ reason: string }>();
const submittingDone = event("submittingDone")();

function createCheckoutActor() {
  return new Actor({
    inputs: [submitBasicInfo, submitShipping, submitPayment, back],
    internal: [paymentOk, paymentFail, submittingDone],
    states: [basicInfo, shippingAddress, payment, submitting, success, error],
    initial: basicInfo,
    context: {} as CheckoutContext,
    setup: (m) => {
      m.on(basicInfo, submitBasicInfo, (event, { context }) => {
        const s = context.get();
        s.basicInfo = event.payload;
        context.set(s);
        return { state: shippingAddress };
      });
      m.on(shippingAddress, submitShipping, (event, { context }) => {
        const s = context.get();
        s.shippingAddress = event.payload;
        context.set(s);
        return { state: payment };
      });
      m.on(payment, submitPayment, (event, { context }) => {
        const s = context.get();
        s.paymentInfo = event.payload;
        context.set(s);
        return { state: submitting };
      });
      m.on(submitting, paymentOk, () => ({ state: success }));
      m.on(submitting, paymentFail, () => ({ state: error }));
      m.on(submitting, submittingDone, () => ({ state: success }));
    },
  });
}
```

The happy-path pieces work without time or promises, so they can be tested
directly.

## Testing Patterns

### Assert Initial State

```ts
const checkout = createCheckoutActor();
expect(checkout.snapshot().path[0]).toBe("basicInfo");
expect(checkout.snapshot().done).toBeFalsy();
```

### Assert Transition Path

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
expect(checkout.snapshot().path[0]).toBe("shippingAddress");

checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
expect(checkout.snapshot().path[0]).toBe("payment");
```

### Assert Context Changes

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
expect(checkout.context.basicInfo).toEqual({ email: "a@b.com", name: "A" });
expect(checkout.context.shippingAddress).toBeUndefined();
```

The data lands in context, step by step.

### Assert Back Navigation

`back` in `payment` returns to `shippingAddress`:

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
expect(checkout.snapshot().path[0]).toBe("payment");

checkout.send(back.create());
expect(checkout.snapshot().path[0]).toBe("shippingAddress");
```

### Assert Final State

```ts
checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
checkout.send(submitPayment.create({ cardNumber: "1111222233334444" }));
checkout.send(paymentOk.create({ orderId: "ord_1" }));
expect(checkout.snapshot().path[0]).toBe("success");
expect(checkout.snapshot().done).toBe(true);
```

### Assert Side Effects with VirtualClock

In production the machine charges a card via a promise effect. In tests, control
time instead. Give the actor a `VirtualClock`, then advance.

Charge hangs → the 800ms timeout fires → `submittingDone` → `success`:

```ts
const clock = new VirtualClock();
const checkout = new Actor({
  inputs: [submitBasicInfo, submitShipping, submitPayment, back],
  internal: [paymentOk, paymentFail, submittingDone],
  states: [basicInfo, shippingAddress, payment, submitting, success, error],
  initial: basicInfo,
  clock,
  context: {} as CheckoutContext,
  setup: (m) => {
    m.on(basicInfo, submitBasicInfo, () => ({ state: shippingAddress }));
    m.on(shippingAddress, submitShipping, () => ({ state: payment }));
    m.on(payment, submitPayment, () => ({ state: submitting }));
    m.on(submitting, submittingDone, () => ({ state: success }));
    m.effect(submitting, {
      name: "startSubmitTimeout",
      fn: ({ signal, emit, clock }) => {
        clock.setTimeout(800, () => {
          if (!signal.aborted) emit(submittingDone.create());
        });
      },
    });
  },
});

checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
checkout.send(submitPayment.create({ cardNumber: "1111222233334444" }));
expect(checkout.snapshot().path[0]).toBe("submitting");

clock.advance(800); // fast-forward time
expect(checkout.snapshot().path[0]).toBe("success");
```

Deterministic and fast: no fake timers, no sleeps. Same inputs, same trace.

### Assert Promise Effects with settled

The charge resolves → `paymentOk` is emitted → `success`. The emit happens in a
microtask, so `settled()` waits for it:

```ts
function createCheckoutWithCharge() {
  return new Actor({
    inputs: [submitBasicInfo, submitShipping, submitPayment, back],
    internal: [paymentOk, paymentFail, submittingDone],
    states: [basicInfo, shippingAddress, payment, submitting, success, error],
    initial: basicInfo,
    context: {} as CheckoutContext,
    setup: (m) => {
      m.on(basicInfo, submitBasicInfo, () => ({ state: shippingAddress }));
      m.on(shippingAddress, submitShipping, () => ({ state: payment }));
      m.on(payment, submitPayment, () => ({ state: submitting }));
      m.on(submitting, paymentOk, () => ({ state: success }));
      m.effect(submitting, {
        name: "chargeCard",
        fn: ({ signal, emit }) => {
          Promise.resolve("ord_1").then((orderId) => {
            if (!signal.aborted) emit(paymentOk.create({ orderId }));
          });
        },
      });
    },
  });
}

const checkout = createCheckoutWithCharge();

checkout.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
checkout.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
checkout.send(submitPayment.create({ cardNumber: "1111222233334444" }));

await checkout.settled();
expect(checkout.snapshot().path[0]).toBe("success");
```

## Key Takeaways

- **States are nodes.** `state("basicInfo")()` creates a node in the graph
- **Events are edges.** `event("submitBasicInfo")()` defines a possible transition
- **Transitions are the graph.** `(state, event) → newState` maps edges
- **Context is memory.** Survives transitions, holds accumulated data
- **Effects are side effects.** Run on state entry, abort on exit
- **Effect names.** Every effect takes a required camelCase `name`; assert it ran with `harness.assertEffectRan(stateName, effectName)` (or `assertEffectNeverRan` / `wasEffectRun`)
- **`snapshot().path[0]`.** Current state name in graph
- **`VirtualClock`.** Deterministically test time-dependent transitions
- **`settled()`.** Wait for promise effects before asserting
- **`snapshot().done`.** True when actor reached a final state
