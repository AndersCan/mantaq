title: Machines in an application
description: Build a machine with machine(id, { create }), so the app and every test get their own actor, ports and clock.
---

## What

A machine is `machine(id, { create })`: a name and a `create` that builds a fresh actor. Ports are options with defaults.

## Why

A machine in an app talks to the outside world: a payment provider, a timer. If the machine imports them, every test hits the real provider and waits on real time. Passed to `create`, the app gets the real ones and each test gets a fake and a `VirtualClock`.

## How

### A machine with ports and a clock

```ts
import { checkoutMachine, chargeCard } from "./checkout";

// app: one actor, real port, real time
export const checkout = checkoutMachine.create({ chargeCard }).actor;
```

`checkoutMachine` is `machine("checkout", { create })`. `create({ clock, chargeCard })` returns `{ actor }`. Both options are optional: the port defaults to the real provider, the clock to real time. The app calls `checkoutMachine.create({ chargeCard })` once at module scope. Each test calls it again and gets a fresh actor with its own state.

### Test with a fake port and a virtual clock

```ts
import { VirtualClock } from "@mantaq/core";
import { createTestHarness } from "@mantaq/test";
import { checkoutMachine, submitBasicInfo, submitShipping, submitPayment } from "./checkout";

const clock = VirtualClock();
const { actor } = checkoutMachine.create({
  clock,
  chargeCard: (cardNumber) => Promise.resolve(`fake_${cardNumber.slice(-4)}`),
});
const harness = createTestHarness(actor);

harness.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
harness.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
harness.send(submitPayment.create({ cardNumber: "1111222233334444" }));

await actor.settled();
harness.assertStateVisited({ stateName: "success" });
```

The fake is a plain function passed as an option. There is no `vi.mock`, no fake timers, no `as any` and no `waitFor`. `settled()` waits for the promise effect to emit.

### A delay is `withTimeout` on the injected clock

The `chargeCard` effect arms a timeout next to the promise:

```ts
withTimeout(800, { input: input, event: () => paymentTimeout.create() });
```

`withTimeout` schedules on the actor's clock and checks the abort signal when it fires. You don't write `setTimeout` plus an abort listener. In a test, `clock.advance(800)` fires it:

```ts
const slow = VirtualClock();
const { actor: slowActor } = checkoutMachine.create({
  clock: slow,
  chargeCard: () => new Promise<string>(() => {}),
});
const slowHarness = createTestHarness(slowActor);

slowHarness.send(submitBasicInfo.create({ email: "a@b.com", name: "A" }));
slowHarness.send(submitShipping.create({ street: "1 Main", city: "Oslo", zip: "0150" }));
slowHarness.send(submitPayment.create({ cardNumber: "1111222233334444" }));

slow.advance(800);
slowHarness.assertStateVisited({ stateName: "error" });
```

### Stay or self-transition

When an event arrives in a state with a running effect or timer, the handler picks one:

| Handler returns              | Effect                                                                  |
| ---------------------------- | ----------------------------------------------------------------------- |
| `{}`                         | Stay. The state is not left; the effect keeps running.                  |
| `{ state: <current state> }` | Self-transition. The effect is aborted and its entry effect runs again. |

Use `{}` to record data without disturbing the work. Use the self-transition to restart it, for example to reset a timer. Core pins both in `packages/core/src/reentry.test.ts`.

### Export the machine

The inspect Vite plugin draws and fuzzes every `machine(...)` your file exports. It calls `create` with its own `VirtualClock`, so each run gets a fresh actor. Three rules:

- Export `machine("<id>", { create })`; the id is the name on the board and in `?machine=<id>`.
- Give every option of `create` except `clock` a default, so tools can build it.
- A machine with a timer takes `clock` in `create` and passes it to `Actor`. A machine without timers never mentions a clock.

A bare actor export is not a machine for the tools. See [what inspect needs from your file](https://github.com/AndersCan/mantaq/tree/main/packages/inspect#what-it-needs-from-your-file).
