`@mantaq/inspect` fuzzes a machine and checks its structure. Two groups of helpers turn that into vitest assertions, so CI catches design errors without a separate command.

```ts
import { expectAllStatesReached, expectNoDesignErrors, expectReached } from "@mantaq/inspect";
```

Each helper takes an inspect target: an `id` and a `create` function that returns a fresh actor on a `VirtualClock`.

```ts
const target = {
  id: "checkout",
  create: () => createCheckoutActor(),
  source: { file: join(import.meta.dirname, "checkout.ts"), root: import.meta.dirname },
};
```

`source` is how fuzzing learns what each event's payload looks like. Without it (or a `payloads` block), an event whose handler reads its payload cannot be tested with a real one. The three checks then stop instead of passing or failing on an empty event:

```
checkout: fuzzing had no payload for 1 event the machine reads, so this check proves nothing yet:
  - submitPayment: read cardNumber
Pass `source` (payloads from the event types) or `payloads: { submitPayment: [...] }` with a real payload for each case.
```

## Fail on design errors

```ts
import { test } from "vitest";

test("checkout has no design errors", () => {
  expectNoDesignErrors(target);
});
```

`expectNoDesignErrors` throws when it finds:

- a handler or effect that throws under fuzzing,
- an effect that sends an event its state does not handle,
- a declared state with no path from the initial state,
- a state that is not final where nothing can happen (no handler, no effect),
- an input or internal event that no state handles.

The message lists one line per error:

```
checkout has 1 design error:
  - archived can never be reached. No transition leads into archived. From basicInfo, the machine can only reach basicInfo, error, payment, shippingAddress, submitting and success. Add a transition into archived, or remove it.
```

Unreached edges and `onAny` routing warnings are not errors. They show in the visualizer and the Vite plugin's output, and do not fail the test.

The reachability check is static. It reads the graph, so it needs no fuzzing: pass `fuzz: false` to skip the fuzz run. When an edge has an unknown target, the check cannot tell and reports nothing.

## Names

A state or event is reported when every word in its name is a generic status word, so it says how something went but not what: ok, ready, idle, loading, loaded, error, failed, failure, success, succeeded, done, finished, complete, completed, pending, busy, active, waiting, start, started, init, status, result, data, update, updated, change, changed, act, acted. `loading` is vague and `loadingPhotos` is not; `LOAD_FAILED` passes because it says what failed. A state or event with no `/** */` comment above its declaration is reported too.

So is a handler (`m.on`, `m.onAny`) with no comment right before it, named by its event, state, file and line, and a state none of whose `m.effect` calls has one.

These checks need the machine file, so they run on the docs site, with `inspectFile`, and with `source` in `expectNoDesignErrors`. Without the file, they are skipped.

## Tell the fuzzer what to expect

Some bugs are not crashes: the machine runs fine and holds the wrong data. Say what must never happen in a block next to the factory, named `<machine id>Expectations`. It is a partial object per state: list only the context keys you care about.

`neverSee` lists contexts that are a bug in that state, and fuzzing fails when a run reaches one. `mustSee` lists contexts some run has to reach, and fuzzing fails when none does.

```ts
import type { Expectations } from "@mantaq/inspect";

/** What the fuzzer must never see. Delete the line to see the bug go unreported. */
export const checkoutWithBugsExpectations: Expectations<typeof createCheckoutWithBugsActor> = {
  payment: { neverSee: [{ address: "" }] },
};
```

The diagram above is built from this block: `payment` carries a "!" for `payment was reached with {"address":""}`, and Replay runs the events that got there. Editor completion offers state names and context keys, and a typo fails to compile.

- `undefined` means "not set": `{ note: undefined }` matches a context without `note`.
- A must-see miss says no fuzz run reached the context. Add a recorded run to `tests` (see "Assert what gets reached") or raise `fuzz.iterations`.
- In a test, pass the block as `expectations` on the target: `expectNoDesignErrors({ ...target, expectations: checkoutWithBugsExpectations })`. The message lists the hit with an `after:` line of events.
- Payloads for events come from `source` or `payloads`. Without them, an event whose handler reads its payload stops `expectNoDesignErrors`, `expectReached` and `expectAllStatesReached` with a message naming the event and the fields it read.

## Assert what gets reached

Reaching is proof. A state or transition counts as reached when the fuzzer or one of your named `tests` runs visited it.

```ts
test("the happy path is covered", () => {
  expectReached(target, {
    states: ["success"],
    transitions: [{ from: "payment", event: "paymentOk", to: "success" }],
  });
});

test("every state is visited", () => {
  expectAllStatesReached(target);
});
```

A miss is a prompt to look, not proof of a bug: the fuzzer may not have found a path, or a guard may block it. The message says so:

```
checkout missed 1 expected reach:
  - state success was not reached
Add a named run to `tests`, or raise `fuzz.iterations`, to cover it.
```

Fix a miss by adding an example run, or by raising `fuzz.iterations` (default 2000):

```ts
const target = {
  id: "checkout",
  create: () => createCheckoutActor(),
  tests: [
    {
      name: "basic info, then shipping",
      steps: [
        { kind: "event", event: "submitBasicInfo", payload: null },
        { kind: "event", event: "submitShipping", payload: null },
      ],
    },
  ],
  fuzz: { iterations: 5000 },
};
```

Naming a state or transition the machine does not declare also fails, with "does not exist". Omit `to` in a transition to accept any target.

## Stable in CI

Runs are seeded, so the same machine gives the same result on every run. Pass `fuzz: { seed }` to change the seed.

## Custom checks

`designErrors`, `unreachableStates`, `missedReach` and `reachedStates` return the same data as lines or ids when you want your own assertion. They take the machine from `inspect(target).machine`.
