Mantaq. TypeScript state machine library.

Actors. Events. Hierarchical states. Three concepts.

## Core ideas

- **Actor** — state machine. Has context, states, effects, transitions, clock.
- **State** — node in graph. Optional: mark final.
- **Event** — typed message. Triggers transitions.
- **Effect** — runs on state entry. Aborts on exit.
- **Context** — mutable record. Survives transitions.

## Packages

| Package         | What                                                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `@mantaq/core`  | Runtime. `Actor`, `state`, `event`, `VirtualClock`                                                                           |
| `@mantaq/sugar` | Helpers. `matches`, `states`, `events`, `tag`, `isIn`, `activeLeaves`, `ActorMap`, `broadcast`, `withPromise`, `withTimeout` |

## The docs story

The whole docs build **one example**: a multi-step checkout form.

Buyer fills basic info, shipping address, payment. System charges card, shows
result. Every page adds a piece to the same machine.

```
basicInfo → payment → success (final)
```

Full flow later. More states, more events, effects, testing.

## Quick example

Minimal slice. Three states, two events. The checkout form, cut to bone.

```ts
import { Actor, state, event } from "@mantaq/core";

const basicInfo = state("basicInfo")();
const payment = state("payment")();
const success = state("success")().final();

const submitBasicInfo = event("SUBMIT_BASIC_INFO")();
const submitPayment = event("SUBMIT_PAYMENT")();

const checkout = new Actor({
  inputs: [submitBasicInfo, submitPayment],
  states: [basicInfo, payment, success],
  initial: basicInfo,
  setup: (m) => {
    m.on(basicInfo, submitBasicInfo, () => ({ state: payment }));
    m.on(payment, submitPayment, () => ({ state: success }));
  },
});

checkout.send(submitBasicInfo.create());
checkout.snapshot().path[0]; // "payment"
```

`success` is final. Actor stops there. Entering it fires `"done"` subscribers.

:::tip[Sugar exists]
Core API verbose on purpose. Shows what happens under hood.

`@mantaq/sugar` has helpers: `matches(checkout, "payment")` instead of `snapshot().path[0] === "payment"`. Batch creation, effect helpers, state grouping.

Learn core first. Sugar second. You'll know _why_ each helper exists.
:::
