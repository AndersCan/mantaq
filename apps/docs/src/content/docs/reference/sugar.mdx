## `matches(actor, pattern)`

```ts
function matches(actor: { snapshot(): Snapshot }, pattern: string): boolean;
```

Dot-separated pattern. Snapshot tree.

```ts
matches(checkout, "payment"); // flat
matches(checkout, "basicInfo.fraud.scanning"); // hierarchical
matches(checkout, "basicInfo.fraud.cleared"); // parallel region
```

Prefix match. Checks top-level state name first, then descends only through region names in order. Ends at a state boundary. `matches(actor, "connected")` → true only if top-level state is `connected`. Not "anywhere inside". That's `isIn`.

## `states(...entries)`

```ts
function states(
  ...entries: Array<string | { name: string; final?: boolean }>
): Record<string, StateRef>;
```

Batch state creation. Entries are strings, or objects with `final: true` for a
terminal state. `success` is final right at creation. No `.final()` call.

```ts
const s = states("basicInfo", "payment", { name: "success", final: true }, "error");
s.basicInfo.name; // "basicInfo"
s.success.isFinal; // true
```

## `events(...names)`

```ts
function events<T extends string>(...names: T[]): { [K in T]: EventRef<K> };
```

Batch event creation.

```ts
const e = events("submitBasicInfo", "submitPayment", "back");
e.submitBasicInfo.create(); // { type: "submitBasicInfo" }
```

## `tag(...stateRefs)`

```ts
function tag(...stateRefs: StateRef<string, unknown>[]): Tag;
```

Group states. `tag.has(snapshot)` → true if any active.

```ts
const busy = tag(s.payment, s.submitting);
busy.has(checkout.snapshot()); // true if paying or submitting
```

## `ActorMap`

Keyed registry of one actor type.

```ts
const map = new ActorMap(createOrderWorker);

map.spawn("ord_1");
map.spawn("ord_2");
map.send("ord_1", ship.create());
map.kill("ord_1");
```

`new ActorMap(factory, options?)`. `factory` builds the actor, receiving the
key: `(id: string) => Actor`. Every `spawn(key)` creates a fresh instance of
the same actor, keyed by id. `options: { autoReap? }`: `true` removes a child
once it reaches a final state (or dies into `__error`). Off by default;
completed children linger until `kill`.

| Method             | What                                   |
| ------------------ | -------------------------------------- |
| `spawn(key)`       | Fresh instance via the factory.        |
| `ensure(key)`      | No-op if exists.                       |
| `send(key, event)` | Send to child.                         |
| `kill(key)`        | Abort. Remove.                         |
| `has(key)`         | Exists?                                |
| `keys()`           | List keys.                             |
| `snapshot(key)`    | Child snapshot. `undefined` if absent. |
| `size`             | Count.                                 |

## `actorSpec(config)`

```ts
function actorSpec<
  const States extends readonly AnyStateRef[],
  const Inputs extends readonly AnyEventRef[],
  const Internal extends readonly AnyEventRef[] = readonly [],
  const Outputs extends readonly AnyEventRef[] = readonly [],
  ActorContext = Record<string, unknown>,
  const Initial extends AnyStateRef | { state: AnyStateRef; payload?: unknown } = AnyStateRef,
>(config: {
  states: States;
  inputs: Inputs;
  internal?: Internal;
  outputs?: Outputs;
  context?: ActorContext;
  initial: Initial;
  clock?: Clock;
  regions?: Record<string, AnyActor>;
  internalBudget?: number;
}): {
  states: States;
  inputs: Inputs;
  internal?: Internal;
  outputs?: Outputs;
  context?: ActorContext;
  initial: Initial;
  clock?: Clock;
  regions?: Record<string, AnyActor>;
  internalBudget?: number;
};
```

Build the actor's static spec: states, inputs, internal/output events,
context, initial state, clock, regions, budget. Returns the value, narrowing
the state/event arrays to their literals (no `as const`) and keeping the
context mutable. Feed it to `definePart<typeof x>` and `withParts`.

```ts
const checkout = actorSpec({
  inputs: [submitBasicInfo, submitShipping],
  internal: [paymentOk, paymentFail],
  states: [basicInfo, shippingAddress, payment, submitting],
  initial: basicInfo,
  context: {} as CheckoutContext,
});
```

`typeof checkout` is the anchor you pass to `definePart`. `ActorSpec` is the
type of such a value; `BuilderOf<ActorSpec>` is its builder.

## `definePart(fn)`

```ts
function definePart<S extends ActorSpec = never>(fn: (m: BuilderOf<S>) => void): Fragment<S>;
```

Wrap a slice of an actor's setup (`m.on`, `m.onAny`, `m.effect` calls) so it
can live in its own file. The generic is required: omit the spec anchor and
`S` defaults to `never`, so registering anything is a compile error rather
than a silent loss of typing. Anchor against an `actorSpec` value:

```ts
const basicInfoPart = definePart<typeof checkout>((m) => {
  m.on(basicInfo, submitBasicInfo, (event, opts) => {
    const cur = opts.context.get();
    cur.basicInfo = event.payload;
    opts.context.set(cur);
    return { state: shippingAddress };
  });
});
```

`typeof checkout` anchors every type in the part: states, events, context,
outputs. Import it type-only in the part file, `import type { checkout } from
"./checkout.ts"`, and keep the refs as value imports.

## `use(m, part)`

```ts
function use<S extends ActorSpec>(m: BuilderOf<S>, part: Fragment<S>): void;
```

Register a part inside a hand-written setup.

```ts
setup: (m) => {
  use(m, basicInfoPart);
  use(m, submittingPart);
};
```

`use` is not the React hook. It takes `Fragment`s produced by `definePart`.
define parts with `definePart`, never annotate the `Part` type by hand.

## `withParts(base, parts)`

```ts
function withParts<
  const States extends readonly AnyStateRef[],
  const Inputs extends readonly AnyEventRef[],
  const Internal extends readonly AnyEventRef[] = readonly [],
  const Outputs extends readonly AnyEventRef[] = readonly [],
  ActorContext = Record<string, unknown>,
>(
  base: Omit<ActorOptions<States, Inputs, Internal, Outputs, ActorContext>, "setup">,
  parts:
    | Part<States, Inputs, Internal, Outputs, ActorContext>
    | readonly Part<States, Inputs, Internal, Outputs, ActorContext>[],
): Actor<States, Inputs, Internal, Outputs, ActorContext>;
```

Build an actor from a spec plus one part or an array of parts. The `setup` is
generated. Every part runs against the builder in order. `base` takes every
option `new Actor` takes: `clock`, `regions`, `internalBudget`, and initial
with payload included.

The parts array shares the actor's generics: `Part<States, ...>`, not any
actor. A part built against one spec cannot be wired into another.

For the same (state, event), the last registered handler wins, across parts
and inline code alike. Effects append instead: every effect on a state runs on
entry.

```ts
const actor = withParts(checkout, [basicInfoPart, submittingPart, backPart]);
```

## Types

```ts
type ActorSpec;       // shape of the static actor spec (states/inputs/.../initial)
type BuilderOf<S>;    // ActorBuilder for that spec
type Fragment<S>;     // (m: BuilderOf<S>) => void
type Part<S, I, Int, O, C>; // (m: ActorBuilder<S, I, Int, O, C>) => void — withParts array element type
```

`ActorSpec` is the type `definePart` and `use` accept. `BuilderOf` and
`Fragment` name the part signature for explicit annotations. `Part` is the
same shape with explicit generics: what `withParts` takes, one or an array.

`ActorSpec` is a constraint, not a value annotation: annotating the value with
`ActorSpec` (or `ActorOptions`) erases its literal state/event/context types.
Build specs with `actorSpec` and pass `typeof <that value>`; never annotate
the object itself.

## `onOutput(actor, handler)`

```ts
function onOutput(actor: AnyActor, handler: (event: InternalEvent) => void): void;
```

Route an actor's emitted outputs to a handler. `regions` auto-wire child outputs
into the parent; `ActorMap` children do not. This is the public wrapper for that
wiring. One call connects a child's declared outputs to a receiver.

```ts
onOutput(childActor, (event) => {
  // handle emitted output
});
```
