## `matches(actor, pattern)`

```ts
function matches(actor: { snapshot(): Snapshot }, pattern: string): boolean;
```

Dot-separated pattern. Snapshot tree.

```ts
matches(checkout, "payment"); // flat
matches(checkout, "basicInfo.fraud.scanning"); // hierarchical
matches(checkout, "basicInfo.fraud.cleared"); // parallel region
```

Prefix match. Checks top-level state name first, then descends only through region names in order. Ends at a state boundary. `matches(actor, "connected")` → true only if top-level state is `connected`. Not "anywhere inside" — that's `isIn`.

## `states(...entries)`

```ts
function states(
  ...entries: Array<string | { name: string; final?: boolean }>
): Record<string, StateRef>;
```

Batch state creation. Entries are strings, or objects with `final: true` for a
terminal state. `success` is final right at creation — no `.final()` call.

```ts
const s = states("basicInfo", "payment", { name: "success", final: true }, "error");
s.basicInfo.name; // "basicInfo"
s.success.isFinal; // true
```

## `events(...names)`

```ts
function events<T extends string>(...names: T[]): { [K in T]: EventRef<K> };
```

Batch event creation.

```ts
const e = events("submitBasicInfo", "submitPayment", "back");
e.submitBasicInfo.create(); // { type: "submitBasicInfo" }
```

## `tag(...stateRefs)`

```ts
function tag(...stateRefs: StateRef<string, unknown>[]): Tag;
```

Group states. `tag.has(snapshot)` → true if any active.

```ts
const busy = tag(s.payment, s.submitting);
busy.has(checkout.snapshot()); // true if paying or submitting
```

## `ActorMap`

Keyed registry of one actor type.

```ts
const map = new ActorMap(createOrderWorker);

map.spawn("ord_1");
map.spawn("ord_2");
map.send("ord_1", ship.create());
map.kill("ord_1");
```

`new ActorMap(factory, options?)` — `factory` builds the actor, receiving the
key: `(id: string) => Actor`. Every `spawn(key)` creates a fresh instance of
the same actor, keyed by id. `options: { autoReap? }` — `true` removes a child
once it reaches a final state (or dies into `__error`). Off by default;
completed children linger until `kill`.

| Method             | What                                   |
| ------------------ | -------------------------------------- |
| `spawn(key)`       | Fresh instance via the factory.        |
| `ensure(key)`      | No-op if exists.                       |
| `send(key, event)` | Send to child.                         |
| `kill(key)`        | Abort. Remove.                         |
| `has(key)`         | Exists?                                |
| `keys()`           | List keys.                             |
| `snapshot(key)`    | Child snapshot. `undefined` if absent. |
| `size`             | Count.                                 |

## `definePart(fn)`

```ts
function definePart<M extends Machine>(fn: (m: BuilderOf<M>) => void): Fragment<M>;
```

Wrap a slice of a machine's setup — `m.on`, `m.onAny`, `m.effect` calls — so
it can live in its own file. Type against the machine options object:

```ts
const checkoutPart = definePart<typeof checkout>((m) => {
  m.on(basicInfo, submitBasicInfo, (event, opts) => {
    const cur = opts.context.get();
    cur.basicInfo = event.payload;
    opts.context.set(cur);
    return { state: shippingAddress };
  });
});
```

`typeof checkout` is the machine options object. It anchors every type in the
part: states, events, context, outputs.

## `use(m, part)`

```ts
function use<M extends Machine>(m: BuilderOf<M>, part: Fragment<M>): void;
```

Register a part inside a hand-written setup.

```ts
setup: (m) => {
  use(m, checkoutPart);
  use(m, submittingPart);
};
```

## `withParts(base, parts)`

```ts
function withParts<
  const States extends readonly AnyStateRef[],
  const Inputs extends readonly AnyEventRef[],
  const Internal extends readonly AnyEventRef[] = readonly [],
  const Outputs extends readonly AnyEventRef[] = readonly [],
  ActorContext = Record<string, unknown>,
>(
  base: Omit<ActorOptions<States, Inputs, Internal, Outputs, ActorContext>, "setup">,
  parts: readonly Part<States, Inputs, Internal, Outputs, ActorContext>[],
): Actor<States, Inputs, Internal, Outputs, ActorContext>;
```

Build an actor from machine options plus an array of parts. The `setup` is
generated — every part is run against the builder in order. `base` takes every
option `new Actor` takes: `clock`, `regions`, `internalBudget`, and initial
with payload included.

The parts array shares the machine's generics — `Part<States, ...>`, not any
machine. A part built against one machine cannot be wired into another.

For the same (state, event), the last registered handler wins — across parts
and inline code alike. Effects append instead: every effect on a state runs on
entry.

```ts
const actor = withParts(checkout, [basicInfoPart, submittingPart, backPart]);
```

## Types

```ts
type Machine;      // shape of a machine options object
type BuilderOf<M>; // ActorBuilder for that machine
type Fragment<M>;  // (m: BuilderOf<M>) => void
type Part<S, I, Int, O, C>; // (m: ActorBuilder<S, I, Int, O, C>) => void — the withParts array element type
```

`Machine` is the constraint `definePart` and `use` accept. `BuilderOf` and
`Fragment` name the part signature for explicit annotations. `Part` is the
same shape with explicit generics — the element type `withParts` takes.

`Machine` is a constraint, not a value annotation: annotating a machine with
`Machine` (or `ActorOptions`) erases its literal state/event/context types.
Always pass `typeof <your options object>` — never annotate the object itself.

## `withPromise(promise, signal, emit, events)`

```ts
function withPromise<T>(
  promise: Promise<T>,
  signal: AbortSignal,
  emit: EmitFn,
  events: {
    success: (data: T) => InternalEvent;
    error: (err: unknown) => InternalEvent;
  },
): void;
```

Promise → actor events. Checks `signal.aborted`.
