# Diagram representability audit

Issue: AndersCan/mantaq#284 (map #283). Base: `origin/main` 9f1c6ec. Planning only, no library change.
All claims cite `packages/<pkg>/src/<file>` and were read in source. Claims marked **[verified]** were also run (scratch script against core, deleted).

## Headline

Core's declaration surface is **nodes + effect names only**. Edges are not data. A handler is an opaque function `(event, {context, actor}) => {state?, payload?, emit?}`; its target, emitted events, and whether it transitions at all are only known by running it (`builder.ts` `on()` stores the fn in `transitions[state][eventType]`; `actor.ts` `applyStateStep` calls it). So:

- Static from `actor.options`: state names, `isFinal`, initial, input/internal event types, which `(state, event)` pairs have a handler, which `Any` events have a handler, effect names per state, region child actors.
- Not static: transition target, internal vs self vs external, emitted event types, effect-emitted events, timers, cross-region sends, whether a branch exists at all.

Consequence for "diagram reflects real machine, never a guess": every edge target is observed or "undetermined", never declared. Observation = real execution on replayed state (map lean). A core remedy is optional and listed below.

## Edge model implied

Every edge in a faithful diagram is one of:

1. **Observed** (state, event, context) -> {target, emits, internal|self|external} from real execution.
2. **Undetermined** (handler exists, not yet probed for this context).
3. **Absent** (no handler -> ignored; or internal event -> `__error`).

"No handler for (state,event)" is the only fully static fact about an edge.

## Can a handler be dry-run on a forked actor without side effects?

**Yes for the handler, with four caveats. No for effects.**

Evidence [verified, scratch script on origin/main]:

- Calling `fork.options.transitions[state][event](event, {context, actor})` directly returns `{state, emit}` as data. Nothing is performed: no queue push, no state change, no effects, no subscribers. `emit` is only a returned array until the actor consumes it (`applyStateStep`).
- A spy `Context({get,set})` captures writes. **But** in-place mutation of `context.get()` mutates whatever object `get` returns (`{n:5}` became `{n:6}` while the spy also saw `set({n:6})`). `get` must return a `structuredClone` per probe.
- A full fork via `new Actor(...)` with cloned context and same setup is isolated (`live` untouched after `fork.send`) **but constructing it runs initial-state effects** (`runEffectList({type:"__init"})`: `effect-A` fired for live and again for fork). Effects doing I/O fire for real. Same for replay: back-navigation by replaying the log on a fresh actor re-runs effects.
- `actorOptions = {...options, transitions, effects}` keeps `setup` and `regions` at runtime (`actor.ts`), but types hide `setup` on `actor.options`, and `regions` are live child instances. A fork needs the machine as a **factory** `() => Actor(...)`, not an instance.

Caveats:

1. Clone context per probe.
2. The `actor` handle: handlers may call `actor.send`, `actor.inject`, `actor.regions.x.send`. Give them the **fork**, never the live actor. Region children must be forked too (factory covers this).
3. Closure side effects (module vars, `fetch`, `console`, `Date`) are not interceptable. Core's determinism guard covers `packages/core/src` only, not user handlers. Handler purity is an unverified assumption; surface it.
4. A handler may throw. `Actor` turns throws into `__error`; a probe sees an exception. With real replayed events and context, a throw is a real finding: report "threw on <input>", not "undetermined".

Effects: not dry-runnable as-is. Options: (a) fork factory built with a setup wrapper whose builder drops `effect()` (`ActorBuilder` is a plain interface, wrapper feasible); (b) `options.clock` is injectable so timers are safe under `VirtualClock`, but I/O inside effects is not. Effect behaviour is then telemetry only (`TransitionInfo.effects`, `pendingTimers()`).

## Remedies (options, not decisions)

A. **No core change.** Observed-edge model: replay real log on a factory-built fork, dry-run handlers on cloned context, record `{target, emit, kind}`. Everything else "undetermined". Zero core budget. Limit: a never-exercised branch stays undetermined.
B. **Core adds optional declared outcome metadata on `on()`**, e.g. `targets: [...]`, `emits: [...]` (names only, not guards), **verified at runtime** (actual result must be a subset, else `__error`). Completes the static diagram; handler stays opaque. Costs export/impl budget (`vp run guard`); design decision for the human session; conflicts with "one way of doing things" if both styles coexist.
C. **Telemetry in core/sugar**: `withTimeout` passes `eventName` (tiny); effect `emit` reported via a subscriber or `TransitionInfo`-like hook (new surface).
D. **`__error` and `Any` wildcard as first-class diagram elements** in the viewer model (no core change).
E. **Resolve region vocabulary**: document "region = peer child actor, always active" in the spec, or implement real compound states (large core change, out of scope).
F. **Factory contract**: viewer loads `() => Actor(...)`; instances cannot be forked because `regions` are live objects.
